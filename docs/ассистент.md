# Ассистент и календарь

Код ассистента живёт в `app/assistant`. Сейчас там пустой пакет. Календарь уже умеет задачи, встречи и напоминания. Ассистент вызывает эти функции в том же процессе и в той же базе. Отдельный HTTP-сервис и свои запросы к таблицам ему не нужны.

Контракт полей и кодов ошибок — `docs/API-контракт.docx`. Этот файл говорит, какие функции звать из Python. HTTP в `app/api` остаётся контрактом экрана на React.

## Куда смотреть

| Путь | Зачем |
| --- | --- |
| `app/assistant/` | Место для распознавания, диалога и выбора действия |
| `app/calendar/tasks.py` | Задачи |
| `app/calendar/meetings.py` | Встречи |
| `app/calendar/reminders.py` | Напоминания |
| `app/calendar/schedule.py` | Сводка за период |
| `app/db/models.py` | Поля записей: `Task`, `Meeting`, `Reminder`, `User` |
| `app/auth/security.py` | `decode_access_token` достаёт id пользователя из access token |
| `app/db/session.py` | Сессия SQLAlchemy. `get_session` сам не делает commit |
| `admin/` | Проверочный экран календаря. Это не интерфейс продукта и не место для ассистента |

Пользователь приходит уже как объект `User`. Его id берётся из токена вызывающего, не из текста команды. Часовой пояс лежит в `user.timezone`, по умолчанию `Europe/Moscow`.

## Что решает ассистент

В функции календаря уходят абсолютные значения и конкретные id.

- Дата задачи — `datetime.date` в поясе пользователя. Момент встречи и напоминания — `datetime` с часовым поясом.
- «Завтра», «утром» (08:00), «днём» (12:00), «вечером» (18:00) ассистент переводит в такую дату или момент сам.
- «Её» и другие отсылки к прошлой реплике ассистент превращает в id записи, которую уже видел.
- Конец встречи можно не передавать: функция поставит час после начала. Если меняется только начало, длительность сохраняется: в `update_meeting` передайте `update_start=True` и `update_end=False`.

Чужая или отсутствующая запись выглядит одинаково: `TaskNotFound`, `MeetingNotFound` или `ReminderNotFound`.

## Функции

У каждой функции первые аргументы — `session` и `user`.

Задачи, `app/calendar/tasks.py`:

| Вызов | Результат | Исключение |
| --- | --- | --- |
| `create_task(..., description, due_on)` | `Task`. `due_on=None` — задача без срока | `DueInThePast`, поле `due_on` |
| `update_task(..., description, due_on, update_description, update_due_on)` | `Task`. Флаг говорит, что поле пришло. `update_due_on=True` и `due_on=None` снимает срок | `DueInThePast`, `TaskNotFound` |
| `complete_task` / `reopen_task` | `StatusChange`: запись и `status_changed` | `TaskNotFound` |
| `delete_task` / `get_task` | удаление или `Task` | `TaskNotFound` |
| `list_tasks(..., TaskListQuery)` | `TaskPage` | `InvalidTaskQuery` |

`TaskListQuery.status`: `active`, `completed`, `all`. `due`: `any`, `dated`, `undated`. Период — пара `date_from` и `date_to`. Сегодня для срока допустим, вчера — нет.

Встречи, `app/calendar/meetings.py`:

| Вызов | Результат | Исключение |
| --- | --- | --- |
| `create_meeting(..., title, starts_at, ends_at, allow_overlap)` | `CreatedMeeting`: встреча и список `overlaps` | `MeetingInThePast`, `InvalidMeetingInterval`, `MeetingOverlap` |
| `update_meeting(..., title, starts_at, ends_at, update_title, update_start, update_end, allow_overlap)` | тот же `CreatedMeeting`. Своя встреча из конфликтов исключена | те же и `MeetingNotFound` |
| `delete_meeting` / `get_meeting` | удаление или `Meeting` | `MeetingNotFound` |
| `list_meetings(..., MeetingListQuery)` | `MeetingPage` | `InvalidMeetingQuery` |

`MeetingOverlap.conflicts` — уже существующие встречи. Запись при этом не создаётся. Повторный вызов с `allow_overlap=True` сохраняет ту же встречу и возвращает пересечения в `CreatedMeeting.overlaps`. Смена одного названия пересечение не проверяет.

Интервал длиннее 24 часов и конец не позже начала приходят как `InvalidMeetingInterval.errors`: пары `(поле, код)`. Момент раньше чем на 60 секунд от текущего времени — `MeetingInThePast` с именем поля.

Напоминания, `app/calendar/reminders.py`: `create_reminder`, `update_reminder`, `delete_reminder`, `get_reminder`, `list_reminders`. Текст и `fire_at` обязательны при создании. Прошлое время — `ReminderInThePast`. У уже сработавшего напоминания новый будущий `fire_at` возвращает статус `pending` и очищает `fired_at`. Правка одного текста статус не меняет. Срабатывания и уведомления в коде ещё нет: функция только хранит запись.

Сводка, `app/calendar/schedule.py`: `list_calendar(..., date_from, date_to, types)`. `types=None` — все три вида, иначе строка `task,meeting,reminder`. Окно не длиннее 366 дней. Задача без срока в сводку не входит. Выполненные задачи и сработавшие напоминания входят. Ошибка запроса — `InvalidCalendarQuery`.

## Сессия

`create_*` и `delete_*` делают `flush` и оставляют commit вызывающему. `update_*`, `complete_task` и `reopen_task` коммитят сами. После создания или удаления нужен `session.commit()`, иначе `get_session` закроет сессию и запись исчезнет.

Один вызов ассистента работает с одной сессией. Повторный commit после функции, которая уже закоммитила, безопасен.

`Idempotency-Key` относится к HTTP в `app/idempotency.py`. Из ассистента его вызывать не нужно.

## Голос

Экран на React берёт микрофон или текст и передаёт кадры звука либо текст в этот бэкенд. Распознавание и выбор функции — в `app/assistant`. Ответ пользователю собирается там же из результата функции или из исключения.

Маршруты `/api/v1/...` для этого не дублируются: их вызывает экран календаря. Поиск, импорт CSV и доставка уведомлений в контракте описаны, в коде их ещё нет.
